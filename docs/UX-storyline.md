# 产品主线与使用动线设计

> 状态：M1 设计基线（重写版）
> 目标：**简单好用**。只做主线，主线之外一律不做；主线每一步逐屏打磨；全程进度透明。
> 配套：`M1-spec.md` §1.3（体验红线）

---

## 1. 设计原则（三条，朴素，不展开）

1. **只做主线**：能砍的功能全砍，砍到只剩"学一课 + 复习到期卡 + 进度透明"。
2. **零决策**：用户永远不需要自己决定"下一步做什么"。系统给答案，且是**接着上次**的答案。
3. **全程透明**：进度、来源、去向、原因，全部可见。用户任何时候都能回答三句话——"我在哪""今天做了多少""还差多少"。

---

## 2. 主线功能（就四件事）

| 编号 | 主线功能 | 一句话 |
|---|---|---|
| F1 | **今日任务** | 唯一入口。告诉用户今天做什么、做了多少、还差多少、下一步点哪 |
| F2 | **学一课** | 五步法（精听 → 生词 → 语法 → 跟读 → 听写），每步有明确产出 |
| F3 | **复习** | 到期卡队列，四档评分，评完即告知"下次何时见" |
| F4 | **进度透明** | 贯穿 F1–F3 的硬指标，不是独立功能（见 §4） |

### 2.1 M1 明确不做（砍掉的理由）

| 不做 | 理由 |
|---|---|
| 战报 / 日报 / 周报 | 用户要的"知道进度"由进度环 + 全局进度直接满足，报表是重复建设 |
| 错词本 | 错的卡由 FSRS 自动多出现，不需单独一个"本" |
| 弱项回炉 / 自适应 | 优化层，主线未稳前不做 |
| Anki 导出 | 系统内复习已满足 |
| 多资源（Coffee Break 泛听等） | 分散注意力，主线是 NCE1 |
| **常驻聊天老师** | **降级为「每屏一句引导语」**。聊天面板要求用户"想该问什么"，本身就是负担；老师应是告知者，不是等待对话的对象 |
| 掌握度 / 统计图表 | 数字好看但对"今天做什么"无帮助，且会诱导焦虑 |

---

## 3. 使用逻辑动线（逐屏打磨）

> 约定：每一屏都写清 **必须有什么 / 不能有什么 / 用户动作 / 系统响应**。

### 3.1 打开第一屏（今日任务页）

这是全产品最重要的一屏。用户 3 秒内必须能回答"我今天要做什么、还差多少、现在点哪"。

```
┌──────────────────────────────────────┐
│ 9月4日 周五                            │
│                                      │
│ 今天两件事，约 45 分钟。先复习，再学 L24。  │ ← 老师的一句话
│                                      │
│         ╭─────────╮                   │
│         │   40%   │                   │ ← 今日进度环
│         │ 18/45分 │                   │
│         ╰─────────╯                   │
│                                      │
│  ① 复习到期卡        ✓ 12/12   已用18分 │
│  ② 学 L24·五步法     ▓▓░░░ 2/5        │
│                                      │
│  ┌────────────────────────────────┐  │
│  │  继续：L24 第 3 步 · 语法讲解     │  │ ← 唯一主按钮
│  └────────────────────────────────┘  │
│                                      │
│ ──────────────────────────────────── │
│  你在 L24 / 共 144 课        ▓░░░ 16%  │ ← 全局进度，常驻
└──────────────────────────────────────┘
```

- **必须有**：老师一句话（今天干什么）、今日进度环（%+分数）、每项任务 `已做/总数` + 状态、唯一主按钮（接着上次的下一步）、全局进度（第几课/共几课）。
- **不能有**：任何图表、任何推荐、任何"你可能感兴趣"、任何第二个同等重量的按钮、任何需要用户做决定的选择。
- **用户动作**：看一眼 → 点主按钮。
- **系统响应**：直接进入"上次中断的那一步"（不是回到课程列表让用户找）。

### 3.2 复习一张卡

```
┌──────────────────────────────────────┐
│ ← 今日              复习 5 / 12        │ ← 第几张/共几张
│ ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░               │
│                                      │
│            glasses                   │ ← 大字卡面
│           /ˈɡlɑːsɪz/                 │
│                                      │
│  来自 L23 · 第 2 次见                  │ ← 透明：来源 + 见过几次
│                                      │
│ ┌──────────────────────────────────┐ │
│ │           显示答案                │ │ ← 唯一按钮
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

点"显示答案"后，卡面展开释义 + 例句，底部出现四档评分：

```
│         眼镜；玻璃杯                   │
│         These are my glasses.         │
│                                      │
│  忘了    模糊    想起    简单          │
│  10分后  1天后   3天后   7天后         │ ← 每档直接标出"下次何时见"
└──────────────────────────────────────┘
```

- **必须有**：`第几张/共几张`、进度条、卡面、来源（来自哪一课、第几次见）、评分档上**直接写出下次间隔**（这是"透明"的关键——用户能理解系统在算什么）。
- **不能有**：卡堆计数以外的统计、"掌握度"、任何额外设置。
- **用户动作**：自答 → 点显示答案 → 选一档。
- **系统响应**：选完立即显示"下次：3 天后"→ 自动进入第 6 张。全部完成后自动回到今日页。

### 3.3 学一课（五步）

```
┌──────────────────────────────────────┐
│ ← 今日        L24 · 第 3 步 / 5 步      │ ← 第几步/共几步
│ Which glasses?   哪几个玻璃杯？          │
│ ▓▓▓▓▓▓░░░░░░░░                        │
│                                      │
│  ①精听 ②生词 ③语法 ④跟读 ⑤听写          │ ← 五步指示器，当前步高亮
│      ✓     ✓     ●                    │
│                                      │
│  ── 第 3 步 · 语法讲解 ──              │
│  指示代词                              │
│  This/That is… · These/Those are…      │
│  these = 近指复数 / those = 远指复数     │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │        完成第 3 步                 │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

- **必须有**：`第几步/共几步`、五步指示器（含已完成标记）、当前步内容、完成按钮。
- **不能有**：一次性铺开五步的全部内容（会让人望而生畏）、底部"下一课"入口（会诱导跳步）。
- **用户动作**：学当前步 → 点完成。
- **系统响应**：指示器打勾 → 自动进入第 4 步。

五步走完 → **必须给出产出清单**（这是"学的东西不会白学"的透明化）：

```
│  L24 学完了 ✓                          │
│                                      │
│  本课沉淀：生词 8 · 语法 2 · 句型 3      │
│  已加入复习计划，明天会再见              │ ← 透明：产出 → 去向
│                                      │
│  [ 回到今日 ]                          │
└──────────────────────────────────────┘
```

### 3.4 今天全部完成

```
┌──────────────────────────────────────┐
│         ╭─────────╮                   │
│         │  100% ✓ │                   │
│         │ 用了47分 │                   │
│         ╰─────────╯                   │
│  ① 复习 12 张 ✓    ② L24 五步 ✓        │
│                                      │
│  明天：复习 8 张 + 学 L25              │ ← 透明：明日预告
│  你在 L25 / 共 144 课        ▓░░░ 17%  │
└──────────────────────────────────────┘
```

- **必须有**：100% 完成态、用时、明日预告（消除"明天要干嘛"的不确定）。
- **不能有**：庆祝动画堆叠、连续打卡天数的巨大数字（会变成压力源）。
- **关键**：完成后**页面的任务就结束了**，不诱导继续学。今天够了就是够了。

### 3.5 中途被打断（高频真实场景）

用户在第 3 步被叫走，5 分钟后回来：

- **必须有**：重新打开后，主按钮仍是"继续：L24 第 3 步 · 语法讲解"——**精确恢复到中断点**。已完成的步骤/卡片状态不丢。
- **不能有**：任何"欢迎回来"弹窗、任何重新选择入口。
- **验收**：中断后重开，用户零思考就能接上，不损失任何已完成进度。

### 3.6 断了一天 / 一周回来（头号留存场景）

- **必须有**：老师一句话明确说明处理方案，并**降低当次负担**：

  > "你断了 3 天。今天不做新的，只清 8 张最关键的卡（约 12 分钟），其余 34 张分摊到后面几天。"

- **系统行为**：复习队列**有上限**（如单次最多 20 张）；积压按重要性排序，**分批消化**，绝不一堆砸来。
- **不能有**：任何显示"你欠了 42 张"的文案、任何红色警告、任何"连续天数归零"的提示。
- **验收**：用户断 3 天回来，看到的负担**不高于**正常一天，且明确知道"债怎么还"。

### 3.7 只有 5 分钟

- **必须有**：今日页底部一个轻入口 —— "今天只有 5 分钟？只做 5 张最该复习的"。做完后正常打卡，其余顺延。
- **验收**：5 分钟内能完成一次有效的"不断链"动作，且系统认可。

## 4. 进度透明设计（贯穿全产品的硬指标）

用户任何时候都该能回答"我在哪 / 今天做了多少 / 还差多少 / 为什么"。下表是透明的**完整清单**，每一条都是必须实现的：

| # | 用户想知道 | 呈现方式 | 出现位置 |
|---|---|---|---|
| T1 | 我学到哪了？还差多少？ | `你在 L24 / 共 144 课 · 16%` | 今日页底部，常驻 |
| T2 | 今天做了多少？还差多少？ | 进度环（`40%` + `18/45 分`） | 今日页顶部 |
| T3 | 每一项任务进行到哪？ | `复习 12/12` `L24 五步 2/5` | 今日页任务清单 |
| T4 | 现在该干嘛？ | 唯一主按钮，写明精确下一步 | 今日页 |
| T5 | 这张卡哪来的？ | `来自 L23 · 第 2 次见` | 复习卡 |
| T6 | 我评完会怎样？ | 评分档直接标 `10分后/1天后/3天后/7天后` | 复习卡评分区 |
| T7 | 学完这课我得到了什么？ | `沉淀：生词 8 · 语法 2 · 句型 3` | 学课完成页 |
| T8 | 明天要做什么？ | `明天：复习 8 张 + 学 L25` | 今日完成页 |
| T9 | 断了之后债怎么办？ | 老师一句话说明降档 + 分摊方案 | 归来首屏 |
| T10 | 为什么今天安排这个？ | 老师一句话（"因为昨天学了 L23，今天见它的生词"） | 今日页 |

**反例（严禁）**：只显示一个百分比却没有分子分母；显示"掌握度 74%"却不说怎么算的；复习队列只说"有 42 张到期"却不告诉用户怎么消化。

## 5. 用户故事（完整三轮推演见 `docs/user-stories.md`）

| 轮次 | 做什么 | 产出 |
|---|---|---|
| 第一轮 · 发散 | 按 10 个维度穷举，不遗漏、不评判 | 60 条原始故事（冷启动 / 日常 / 复习 / 学课 / 中断 / 时间受限 / 进度 / 系统 / 心理 / 边界） |
| 第二轮 · 细化 | 合并动线相同的，补齐念头 / 动线 / 系统必须给 / 验收 | 27 条核心故事 |
| 第三轮 · 自我论证 | 红队质疑：真实性 / 频率 / 必要性 / 负担检验 / 冲突检验 | M1 需求清单 + 明确不做清单 |

### 5.1 论证中新产生的 7 条关键决策（初版设计里没有）

1. **只给"单调递增"的进度指标**（已完成 N 课），**拒绝"会归零"的连续天数** —— 连续天数一旦断链归零，会直接催生"反正断了，算了"的放弃，与 R7 冲突。
2. **断超 7 天主动提供"重新开始"选项**，而非只给"还债"一条路 —— 此时用户心理上已接近重来，强行消化积压等于逼他放弃。
3. **行为即记录**，取消手动"点完成" —— 系统能感知学习行为（播了句子 / 翻了卡 / 答了卡），就不该让用户记得点按钮。
4. **全局进度以绝对数为主、百分比为辅**（你在 L24 / 共 144 课）—— "走了多远"比"还剩多少"更有成就感，也不会让人焦虑"才 16%"。
5. **日界为次日 4:00** —— 避免凌晨 1 点学完却被算成昨天、还要再学一次。
6. **卡连错 3 次主动换呈现**（补例句 / 拆音节）并告知"系统会更频繁安排它" —— 把挫败转为对系统的信任。
7. **生词不要求当堂记全**，透明说明"会分散到后面几天出现" —— FSRS 天然分散，不需要分批教学。

### 5.2 被自我论证否掉的两个"主流做法"

- **掌握度百分比**：用户知道了能做什么？**无法指导任何行动**，且制造焦虑 → 改为可行动的事实：常错的**具体词**。
- **连续天数（streak）**：主流留存机制，但断链归零会催生放弃 → 用单调递增的"已完成 N 课"替代。

## 6. M1 范围修订建议

原 spec §10 的 M1 范围偏重，建议按下表收敛 —— **把省下的力气全部投入主线动线打磨**：

| 原 M1 范围 | 建议 | 理由 |
|---|---|---|
| 今日任务包 | **做（打磨到极致）** | 唯一入口，F1 核心 |
| 五步学一课 | **做（打磨到极致）** | F2 核心 |
| 复习队列 + FSRS 评分 | **做（打磨到极致）** | F3 核心 |
| 进度透明（T1–T10） | **做（新增，硬指标）** | 用户明确要求 |
| 老师一句话引导 | **做（降级版）** | 每屏一句，非常驻聊天 |
| 每日推送提醒 | **做（极简）** | 一句话："今天 12 张 + L24，约 45 分钟" |
| PWA 可装 | **做** | 手机入口 |
| 战报 / 错词本 / 弱项回炉 | **延后 M2** | 非主线 |
| 外链资源（胶学视频 / 泛听） | **延后 M2** | 主线未稳，先不加 |
| Anki 导出 | **延后** | 系统内复习已够 |

## 7. M1 体验红线（硬约束，纳入 spec 验收）

1. **首屏只有一个主任务**，且主按钮写明精确下一步。
2. **零决策**：用户永不自选"复习还是新课"。
3. **界面结构恒定**：第 1 天到第 365 天核心界面不新增、不重排。
4. **债封顶**：复习队列有上限；中断归来走降档 + 分批，不一次性砸债。
5. **进度处处透明**：T1–T10 每一条必须实现，禁止只给百分比不给分子分母。
6. **每步即时反馈**：完成任何一步都有可见状态变化。
7. **无负罪感**：禁止"你欠了 / 落后了 / 连续中断"等制造焦虑的措辞。
8. **完成后不诱导**：今日任务做完即结束，不推"再来一课"。
